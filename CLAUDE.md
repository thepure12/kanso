# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Shared kanban boards: Nuxt 4 + Nuxt UI 4, Postgres 17 with row-level security, Drizzle ORM, `nuxt-auth-utils` (email/password + Discord/GitHub/Google OAuth). Package manager is pnpm.

## Commands

```bash
pnpm install
cp .env.example .env              # NUXT_SESSION_PASSWORD (32+ chars), OAuth keys optional
pnpm db:up                        # docker compose up -d db: Postgres 17; docker/init.sql creates the 3 roles
pnpm db:migrate                   # drizzle-kit migrate as kanban_owner (MIGRATION_DATABASE_URL)
pnpm dev                          # http://localhost:3000
pnpm typecheck                    # nuxt typecheck (vue-tsc)
pnpm build
pnpm test                         # vitest run — all projects
pnpm vitest run --project db      # one project: db | unit | components | api
pnpm vitest run tests/rls.test.ts             # single file
pnpm vitest run tests/rls.test.ts -t 'viewer' # single test by name
docker compose --profile app up -d --build    # db + migrate (one-off) + app on :3000, all in containers
```

Deployment: `Dockerfile` stages `build` (pnpm via corepack, version from `packageManager`), `migrate` (build stage running `pnpm db:migrate`) and `runtime` (node 22 alpine, only `.output`, user `node`, `NODE_ENV=production`). Compose services `migrate` and `app` sit in profile `app`, read `.env` and override the DB URLs to host `db`. Not built locally (no Docker access when written). `docker-compose.prod.yml` is the server stack: no profiles, role passwords from `.env` (`KANBAN_*_PASSWORD`, passed to `docker/init.sql` as psql variables by `docker/init-prod.sh`; without them init.sql keeps the dev passwords), Caddy (`docker/Caddyfile`, `KANBAN_DOMAIN`) is optional, profile `caddy` via `COMPOSE_PROFILES`; the app is published on `KANBAN_APP_PORT` (default `127.0.0.1:3000`) for a host proxy, Postgres never. `deploy/embedded-pg/` (own `package.json`, installed with npm on the server, not part of the pnpm workspace): `start.mjs` runs Postgres 17 from `embedded-postgres` on 127.0.0.1 for servers with neither Docker nor Postgres, and on each start creates the `kanban` database, roles and schema settings of `docker/init.sql` and sets role passwords from env; systemd units in `docs/DEPLOYMENT.md`. `deploy/install.sh`: interactive install/update for a dedicated non-root user (refuses root): `systemd-embedded` | `systemd-pg` | `docker`; systemd user units (`kanso.service`, `kanso-pg.service`, needs `loginctl enable-linger`), files under `~/.local/share/kanso`, settings for re-runs in `~/.config/kanso/install.conf`, writes an Apache snippet; `--dry-run` prints instead, `KANSO_INPUT=<file>` feeds answers in tests. CI: `.github/workflows/ci.yml` runs postgres:17, `docker/init.sql` via psql, `cp .env.example .env`, migrate, typecheck and every vitest project.

Vitest projects (`vitest.config.ts`), files run serially (`fileParallelism: false`):
- `db` — `tests/*.test.ts`. Hit the real database (no mocks), connecting as `kanban_app` / `kanban_auth` with URLs from `.env`. Need Postgres running and migrated.
- `unit` — `tests/unit/`: pure helpers in `app/utils/` (markdown test uses jsdom; DOMPurify misbehaves under happy-dom).
- `components` — `tests/components/`: `mountSuspended` in the Nuxt environment. `fsModuleCache` is off for it: the cached test-utils entry stub breaks the next run.
- `api` — `tests/api/`: `@nuxt/test-utils/e2e` builds and starts the app (slow), then calls it over HTTP as signed-up users. Uses the global `fetch` with a captured base URL because test-utils' context exists only inside tests. Each user sends its own `x-forwarded-for` to stay under the login rate limit.

## Architecture: Postgres owns authorization

The core design rule: **all permission logic lives in Postgres (RLS policies, `SECURITY DEFINER` functions, triggers). The app holds none.** Do not add role checks in route handlers; add or change policies instead.

Three DB roles (`docker/init.sql`), each with its own connection URL:
- `kanban_owner` — migrations only; owns tables and `app.*` functions. RLS is ENABLEd, not FORCEd, so owner-defined `SECURITY DEFINER` helpers bypass policies (avoids recursion).
- `kanban_app` — all board/card/team requests (`NUXT_DATABASE_URL`). `NOBYPASSRLS`; cannot read `password_hash` or `oauth_accounts`.
- `kanban_auth` — login/register/OAuth callbacks only (`NUXT_AUTH_DATABASE_URL`, via `useAuthDb()`).

Request flow (`server/utils/`, auto-imported by Nitro):
- `defineUserHandler(fn)` (`session.ts`) requires a session (or an API token, see below), then calls `withUser(userId, tx => ...)` (`db.ts`), which opens a transaction on the `kanban_app` pool and runs `set_config('app.user_id', id, true)`. Transaction-local, so pooled connections never leak identity. Every authenticated API route uses this wrapper. It also sets `app.client_id` from the `x-client-id` header (the browser tab), used by board change notifications.
- DB errors thrown by RLS/triggers/constraints are mapped to HTTP errors by `toHttpError` (`errors.ts`): `42501`→403, `P0002`→404 (unknown email), `23514`→409 (last owner; card date/estimate checks → 400), `23503`/`22P02`→400. An RLS-filtered `UPDATE`/`DELETE` affects zero rows rather than erroring, so handlers use `.returning()` and `notFound(...)` when no row comes back.
- Input validation: zod v4 via `readValidated(event, schema)` (400 whose `statusMessage` names the first issue, e.g. `title: Too big: ...`, issues in `data.issues`; `useApiError` translates known ones) and `paramsValidated(event, uuidParam)`.
- Operations that need privileged lookups go through `app.*` SQL functions called with `tx.execute(sql\`select ... app.fn(...)\`)`: `app.create_board`, `app.add_board_member`, `app.create_team`, `app.add_team_member`, `app.board_role` (effective role = stronger of direct board role and team role).

Other invariants enforced in SQL (see `server/db/migrations/0001_rls.sql`, `0003_teams_rls.sql`):
- A board's team is fixed at creation (column-level `UPDATE` grant on `boards.name` only).
- Triggers keep at least one owner per team and per personal board.
- `cards (column_id, board_id)` has a composite FK to `columns (id, board_id)`, so cards cannot move across boards. Likewise `card_tags` carries `board_id` with composite FKs to `cards (id, board_id)` and `tags (id, board_id)`, so a card only carries tags from its own board.
- Column rules (`column_rules`, `0008`, `0010`, `0012_card_features_rls.sql`): `kind` enum (`apply_tag`, `remove_tag`, `assign_to`, `set_due`) plus kind-specific columns (`tag_id`, `user_id`, `due_days`; check `column_rules_kind_fields`). They run when a card is inserted or its `column_id` changes (reorder within a column does not re-run them); a newly added tag/assignee rule is also applied by `POST /api/columns/:id/rules` to the column's current cards (not templates/archived; `set_due` is not): AFTER trigger `cards_apply_column_rules` adds/removes tags and adds assignees (skipping people who lost board access), BEFORE trigger `cards_set_column_rule_fields` sets `due_date` (at most one `set_due` per column). New rule kinds: add to the enum, the check, the matching trigger, `toColumnRule` (`server/utils/rules.ts`) and `ColumnRulesModal.vue`. A migration that adds an enum value cannot use it as a literal in the same transaction (drizzle-kit runs all pending migrations in one), so compare `kind::text` there.
- Cards: titles up to `CARD_TITLE_MAX` (1000, `shared/cards.ts`; check `cards_title_length`, kept in step by hand). Several assignees in `card_assignees`; `due_date`, `priority` enum, `archived_at` (archived cards stay in their column but are left out of `GET /api/boards/:id`). `checklist_items`, `card_comments`, `card_attachments` (bytea, 10 MB, served with `nosniff` and forced download except safe image/PDF types) and `card_activity` all carry `board_id` with a composite FK to `cards (id, board_id)`.
- Card schedule, time, cover (`0029_card_schedule_time_rls.sql`): `cards.start_date` (check `cards_start_before_due`; a `set_due` rule pulls a later start back to the new due date), `estimate` numeric(6,2) >= 0 (story points; column header sums visible cards), both logged as activity kinds `start`/`estimate` and copied by `copy_board`/export/import (optional fields, export stays `version: 1`). `time_entries` (minutes > 0, `spent_on`, `note`; nullable `user_id`): viewers read, editors insert their own, authors update theirs, authors or owners delete (like comments); `POST /api/cards/:id/time`, `PATCH`/`DELETE /api/time-entries/:id`, `GET /api/cards/:id` adds `timeEntries` + `timeTotal`, board cards carry `timeMinutes`. Durations are parsed by `app/utils/duration.ts` (`CardTime.vue`). `cards.cover_attachment_id` FK `ON DELETE SET NULL`; trigger `cards_check_cover` requires an image (png/jpeg/gif/webp) of the same card, else `KB003`→400. `toHttpError` maps `23514` on `cards_start_before_due`/`cards_estimate_range` to 400 by constraint name; other `23514` stay 409.
- `card_activity` is written only by SECURITY DEFINER triggers through `app.log_activity` (not executable by `kanban_app`). Card PATCH diffs tag/assignee sets instead of replacing them so the log shows real changes.
- Custom fields (`0033_board_fields_rls.sql`): `board_fields` (`kind` enum text|number|date|select|checkbox|url, fixed at creation via column grants; `options` jsonb `[{id,label,color}]` for select only, checked by trigger `KB006`→400; name unique per board case-insensitively, `position` via `positionBetween(tx, 'field', ...)`, `show_on_card`). `card_field_values (card_id, field_id)` pk, jsonb `value`, composite FKs to cards and board_fields; trigger `app.check_card_field_value` checks the shape per kind (`KB005`→400), mirrored by `isValidFieldValue` (`shared/fields.ts`) for the PUT, import and UI. Removing a select option deletes values using it (trigger). Policies as tags: viewers read, editors manage both. Activity `field` with `{field, kind, from, to}` display text (option labels). API: `POST /api/boards/:id/fields`, `PATCH`/`DELETE /api/fields/:id`, `PUT /api/cards/:id/fields/:fieldId {value|null}`; `Card.fields` / `CardDetail.fields` map field id → value, `BoardDetail.fields`. UI: `BoardFieldsModal`, `CardFields` (saves each value at once), chips in `BoardCard`, select/checkbox filters (`CardFilter.fields`, `fieldFilterKey` in `app/utils/fields.ts`). Export: `fields` (options by label) and per-card `fieldValues` (by field name, select by label); copies keep option ids.
- Column groups (`0051_column_groups_rls.sql`; called "column tags" in the UI, and tags "card tags"; code, keys and routes keep group/tag): `column_groups` (name 1-50, unique per board case-insensitively; `color`; `position` via `positionBetween(tx, 'columnGroup', ...)`) and `column_group_members (group_id, column_id, board_id)` with composite FKs to both (same board only), so a column can be in several groups. Policies as board fields: viewers read, editors manage (`app.can_edit`). API: `POST /api/boards/:id/column-groups`, `PATCH`/`DELETE /api/column-groups/:id` (`columnIds` replaces the members via `setColumnGroupMembers`), `POST /api/boards/:id/columns {groupId?}`; `BoardDetail.columnGroups` (`loadColumnGroups`, `server/utils/columnGroups.ts`, members in column order). Copied by `copy_board`; export `columnGroups: [{name, color, columns: [title]}]` (optional). UI: `ColumnGroupsModal` (board menu, editors), a picker in the board view (localStorage `kanban:column-group:<id>`, `columnsInGroup` in `app/utils/columnGroups.ts`) that narrows the board view and swimlanes only; column drag is off while a group is shown; group chips on column headers select a group; column menu "Groups" toggles membership. Not undoable.
- Board automations (`0056_board_automations_rls.sql`): `board_automations` (`kind` enum `archive_done` | `tag_stale` | `notify_stale` | `raise_priority`, `days`, `tag_id` (tag_stale, composite FK, deleted with the tag), `priority` (raise_priority), `active`, `last_run_at`; check `board_automations_kind_fields` → 400, unique `(board, kind, tag, priority)` nulls not distinct → 409). Viewers read, editors manage (`UPDATE (days, active)` only). Nitro task `server/tasks/cards/automations.ts` (hourly) calls `app.run_board_automations()` as kanban_auth (optional `only_board`, used by tests so they never touch other boards) (only role with EXECUTE; `FOR UPDATE SKIP LOCKED`, unarchived boards, each automation in its own exception block). "Open" cards = not template, not archived, not in the last column (`app.automation_open_cards`); staleness = `app.card_last_activity` (latest `card_activity` or creation); staleness ignores activity of automations; archive_done uses the last created/moved/restored entry. It runs with `app.user_id` empty and `app.automation = 'on'`, so `app.log_activity` writes actor null and `data.automation: true` (shown as "Automation" by `actorLabel` in `activityText.ts`) and the normal triggers notify, fan out and enqueue webhooks. notify_stale logs activity kind `stale` `{days}` (in `fan_out_notification`), at most once per `days` days per card (its own last `stale` entry). API: `POST /api/boards/:id/automations`, `PATCH`/`DELETE /api/automations/:id` (token route); `BoardDetail.automations`. UI: `BoardAutomationsModal` (board menu). Not copied by `copy_board` or export. In dev, run with `GET /_nitro/tasks/cards:automations`.
- `app.copy_board(src, name, team, with_cards)` is SECURITY INVOKER: it copies through the caller's policies. Cards are inserted before rules so rules do not fire on copies. Field definitions and column groups are always copied, field values only with cards.
- Notifications (`0016_notifications_rls.sql`): AFTER INSERT trigger on `card_activity` (`app.fan_out_notification`) writes a `notifications` row per card assignee (not the actor, only while they have board access) for kinds `assigned` (only the assigned user, via `data.user_id`), `commented`, `moved`, `due`, `archived`; boards created in the same transaction (copies) are skipped. It sends `NOTIFY user_notifications {u}`; `GET /api/notifications/events` (SSE) relays it. `kanban_app` can only read, mark read (`read_at`) and delete its own rows. "Due soon" is computed in `GET /api/notifications`, not stored.
- Watchers (`0031_watchers_links_rls.sql`): `card_watchers (card_id, board_id, user_id)`, pk `(card_id, user_id)`. Board viewers read; anyone with board access inserts/deletes only their own row (`PUT`/`DELETE /api/cards/:id/watch`). Trigger `app.auto_watch_card` (on `cards` and `card_comments` insert, `ON CONFLICT DO NOTHING`) makes creators and commenters watch, skipping boards created in the same transaction (copies, imports). `fan_out_notification` sends watchers what assignees get (UNION dedupes; `assigned` still only to the assigned user). `GET /api/cards/:id` returns `watchers` + `watching`; board cards carry `watching`.
- Card links (`0031`): `card_links (board_id, from_card_id, to_card_id, kind card_link_kind: blocks|relates|duplicates, created_by)`, composite FKs for both ends (same board only), unique `(from, to, kind)`, `relates` unique per unordered pair, check `card_links_not_self`. AFTER INSERT trigger `app.check_card_link_cycle` (recursive CTE, advisory lock per board) rejects `blocks` cycles with `KB004`→409; `23505` on `card_links_*`→409, `card_links_not_self`→400. Viewers read, editors insert (as `created_by`)/delete. Trigger logs `linked`/`unlinked` on both cards (`data`: `kind`, `direction` out|in, `card_id`, `card` title). `POST /api/cards/:id/links {toCardId, kind}`, `DELETE /api/card-links/:id`; `GET /api/cards/:id` returns `links` (both directions, via `loadCardLinks`). Board cards carry `blockerIds`; "blocked" is computed client-side by `blockedCardIds` (`app/utils/cardLinks.ts`): a blocker counts while it is on the board (not archived) and not in the board's last column ("done"). Copied by `copy_board` (between copied cards) and export/import (`links: [{from, to, kind}]` by card index, optional; import skips bad indexes, duplicates and cycles, counted in `skipped.links`).
- Invites (`0018_invites_rls.sql`): `app.add_board_member` / `app.add_team_member` record an `invites` row (and return NULL) when no user has the email; the members POST then returns `{ invited: true }`. AFTER INSERT trigger `users_claim_invites` turns a new user's invites into memberships. Members see invites, owners revoke them (`DELETE /api/{boards,teams}/:id/invites/:inviteId`); no direct inserts. The members POSTs mail after commit (`mailNewMember`, `server/utils/memberMail.ts`, via `runAfterCommit` in `session.ts`, failures only logged): an invite with `/register?email=&invite=<token>` (email prefilled; `invite` is a 14-day `invite`-purpose email token with empty user id: registering with it for the same email creates the account verified, which claims invites, and signs in, returning `{ signedIn, twoFactor }` instead of mailing a confirmation) in the inviter's locale, or an "added to" link to `/teams/:id` / `/boards/:id` for an account that was not a member (role changes and self-adds send nothing).
- Rate limiting (`rateLimit` in `server/utils/auth.ts`, `0026_rate_limits_rls.sql`): fixed window per key (default 10 per 15 min, 429 past it) in table `rate_limits`, via `app.hit_rate_limit(key, limit, window)` (SECURITY DEFINER, kanban_auth only; atomic upsert, purges expired rows). Durable and shared across instances, so API tests give each client a random `x-forwarded-for`. Keys: `login:ip:email`, `register:ip`, `forgot:ip`, `reset:ip`, `resend:ip`, `password:user`, `email-change:user`.
- Sign-up gate (`server/utils/signup.ts`, `assertSignupAllowed`): called by register, by `/auth/verify`, and by `upsertOAuthUser` when creating or taking over an unverified account. `NUXT_ADMIN_EMAIL` always passes (the one check in the app, so a fresh install can be set up); everyone else is decided by `app.signup_allowed` (kanban_auth) from `instance_settings`.
- Instance admin (`0022_instance_admin_rls.sql`): single-row `instance_settings` (`signup_mode` open|restricted, default restricted; `allowed_domains`, `allowed_emails`, lower case; `allow_external_invites`) replaces the old signup env vars. Restricted admits allowlisted emails, plus invited ones only when `allow_external_invites`; with it off, `app.add_board_member` / `app.add_team_member` refuse invites to outside emails (`KB001`→403). Rules gate new sign-ups only. Admins are rows in `instance_admins`: `startSession` calls `app.bootstrap_admin` for `NUXT_ADMIN_EMAIL` (verified accounts only); admins promote verified users, `KB002`→409 keeps one admin. `app.remove_user` (admins, not self) hands sole-owned personal boards/teams to the strongest longest-standing member or deletes them when empty; `boards.owner_id`, `cards.created_by` become null. `withUser` returns 401 (and `defineUserHandler` clears the session) once the account is gone. UI: `/admin` (`app/pages/admin.vue`), header link from `GET /api/me`.
- Email verification (`0020_email_verification_rls.sql`): `users.email_verified_at`. Password sign-up creates an unverified user and mails a link (`sendVerificationEmail`, `server/utils/mail.ts`; stateless HMAC token in `server/utils/emailToken.ts`, keyed by `NUXT_SESSION_PASSWORD`); `GET /auth/verify` sets it and starts the session. Login refuses unverified users (403, after the password check). Registering over an unverified email replaces its password; OAuth with a provider-verified email takes it over and clears the password. New OAuth accounts need a provider-verified email. `users_claim_invites` fires only once the email is verified (on insert or on update of `email_verified_at`), so DB tests insert users with `email_verified_at` when they need invites claimed. Mail: `NUXT_MAIL_SMTP_URL`, `NUXT_MAIL_FROM`, `NUXT_PUBLIC_SITE_URL` (link base); without SMTP and with `NUXT_MAIL_LOG_LINKS` (default in dev) the link is logged to the console. API tests mint tokens with `signEmailToken`.
- Sessions carry `sessionVersion` (`users.session_version`); `withUser` returns 401 when it no longer matches. Password reset, password change and email change bump it, signing out other sessions; `startSession` (uses `replaceUserSession`) issues the new one. Email tokens (`emailToken.ts`) are signed per purpose (`email-verify`, `password-reset`, `email-change`, `invite`); reset and email-change tokens carry the version, so they work once.
- Account (`server/api/account/*`, `/account` page, `0024_account_mentions_digest_rls.sql`): credential reads/writes go through `useAuthDb()` after the session check (kanban_app cannot see `password_hash`/`oauth_accounts`); name and `digest_enabled` go through kanban_app (column grants). Email change mails a link to the new address (`GET /auth/confirm-email`); trigger `users_claim_invites_on_email` claims invites for it. Self-delete is `app.delete_my_account()` (`KB002` for the last admin); it and `app.remove_user` share `app.remove_user_internal` (no grants).
- Sessions (`0039_two_factor_sessions_audit_rls.sql`): `user_sessions` row per sign-in; `issueSession` (`server/utils/auth.ts`) inserts it as kanban_auth and stores its id in `session.secure.sessionId` (server-only). `withUser` / `requireLiveSession` (handlers outside withUser: kanban_auth credential routes, SSE) call `app.check_session(sid, version)` once per request: `gone`/`expired` → 401 (bumps `last_seen_at` at most every 5 min). Cookies without a session id (pre-0039) are expired → re-login. A `session_version` bump revokes all the user's rows (trigger). Users read/revoke own rows (`UPDATE (revoked_at)` only, never back to null): `GET /api/account/sessions`, `DELETE /api/account/sessions/:id`, `POST /api/account/sessions/revoke-others`. Sign-out revokes via the `sessionHooks` `clear` hook (`server/plugins/sessions.ts`); inside a `defineUserHandler` use `clearSessionAfterCommit(event)`, never `clearUserSession` (deadlocks on the row lock).
- Two-factor (`server/utils/twoFactor.ts`, `totp.ts`, `secretBox.ts`): `user_totp` (AES-256-GCM secret, `enabled_at`, `last_used_step` for replay) and `user_recovery_codes` (sha256) are kanban_auth only. `startSession` returns `{ twoFactor }`: if enabled it stores only `secure.pendingTwoFactor` (userId, session version, 5 min) and callers send the browser to `/login/2fa` (login/reset JSON `{ twoFactor: true }`; verify, confirm-email and OAuth callbacks redirect). `POST /api/auth/two-factor` takes a TOTP or recovery code (rate limit `2fa:<userId>`) and calls `issueSession`. Already-authenticated renewals (password change, 2FA enable) call `issueSession` directly. Account routes `/api/account/two-factor/{setup,enable,recovery-codes,disable}`; enabling bumps `session_version`. Key: `NUXT_TOTP_KEY` or HKDF of the session password.
- API tokens (`0041_api_tokens_webhooks_rls.sql`, `server/utils/apiTokens.ts`): `api_tokens` (sha256 `token_hash`, `prefix`, `scopes` read|write, `expires_at`, `revoked_at`, `last_used_at`). `kanban_app` lists/creates/revokes own rows (no SELECT on `token_hash`, `UPDATE (revoked_at)` only); `/api/account/tokens` (GET, POST returns the `kb_<base64url 32 bytes>` token once, DELETE `/:id` revokes), `ApiTokenList.vue` on `/account`. `defineUserHandler` takes `Authorization: Bearer` instead of the cookie (`requireTokenUser` in `session.ts`): route must pass `tokenRouteAllowed` (allowlist of h3 route patterns from `event.context.matchedRoute.path`; account, auth, admin, webhooks and any new top-level prefix are refused, 403), then `app.resolve_api_token(hash)` (kanban_auth; bumps `last_used_at` at most every 5 min) → 401 + `rateLimit('token:<ip>', 20)` on failure, then `read` scope allows only GET/HEAD (403). `withUser` gets `{ tokenId }` and skips `app.check_session`; no cookie is read, set or cleared. Tokens ignore `session_version`; `POST /api/auth/reset-password` revokes them (`app.revoke_api_tokens`). Board limits (`0054_api_token_boards_rls.sql`): `api_tokens.board_ids` uuid[] (null = all, 1-100 ids, no FK so deleting a board never widens it; insert policy needs every board visible, else 403), returned by `resolve_api_token`; `withUser` sets `app.token_boards`, and `app.board_role` returns null outside it (`app.token_allows(b)`), so every board policy follows. A limited token caps `app.team_role` at viewer, cannot insert boards or teams (trigger `app.refuse_limited_token`, 42501) and only touches its boards' notifications, stars and watches. `ApiToken.boards` lists names (`toApiTokens`); picker in `ApiTokenList.vue`. Handlers outside `defineUserHandler` (`requireLiveSession`, SSE) are cookie only. New top-level API prefixes meant for scripts must be added to `tokenRoutes`. Docs: `docs/API.md`.
- MCP (`server/api/mcp.ts`, `server/utils/mcp.ts`, `mcpFormat.ts`): stateless Streamable HTTP endpoint for AI agents (`@modelcontextprotocol/sdk`, `WebStandardStreamableHTTPServerTransport`, JSON responses, new server per request; GET/DELETE 405). Bearer API token only, never the cookie (`resolveTokenUser` in `session.ts`; 401 + `WWW-Authenticate`). Write tools are registered only for `write` tokens. Each tool calls an existing REST route through Nitro's in-process `$fetch` (prefixes the base path) with the caller's `authorization`, `x-forwarded-for` and `x-client-id: mcp`, so routes, `tokenRoutes`, scopes and RLS decide everything; no permission logic in tools. A new tool wraps a route tokens may already call. `get_board`/`get_card` return compact views (`boardForAgent`, `cardForAgent`: names next to ids, no display data); `get_card` takes `boardId` because `GET /api/cards/:id` has no card fields. Route errors become `isError` tool results (`<status> <message>`). The token dialog (`ApiTokenList.vue`) shows the URL and a `claude mcp add` command. Tests: `tests/api/mcp.test.ts`. Docs: `docs/API.md`; next steps in `docs/ROADMAP.md`.
- Webhooks (same migration): `board_webhooks` (`format` json|slack|discord, `secret`, `events` = activity kinds, empty = all; `active`, `last_status`, `last_error`, `last_delivery_at`, `failure_count`). Owners only (all four policies); `secret` has no SELECT grant (returned once by `POST /api/boards/:id/webhooks`; `app.webhook_ping_target` gives it to owners for `POST /api/webhooks/:id/test`). ## Sub-path deployments

`NUXT_APP_BASE_URL` (build time; Docker build arg) sets `app.baseURL` in `nuxt.config.ts`, e.g. `/kanso/`. `$fetch`, `useFetch`, `api`, `NuxtLink`, `navigateTo`, assets and Nitro routing follow it (`matchedRoute.path` stays relative). Hand-built URLs must not: use `appUrl('/api/...')` / `basePath()` (`app/utils/basePath.ts`; capture `basePath()` during setup for later callbacks) for EventSource, `<img src>`, `<a href>`, `external` links, `window.location`, and pass it to `backgroundStyle(bg, id, thumb, base)`; server redirects go through `appPath('/login')` (`server/utils/basePath.ts`). OAuth handlers pass `redirectURL: oauthRedirectURL(provider)` (from `NUXT_PUBLIC_SITE_URL`, which includes the path; behind a proxy the request URL is http). PWA manifest uses `baseURL`; workbox `urlPattern`s are serialised into sw.js, so they strip the service worker scope path instead of reading `baseURL`. Under a base path the session cookie is `kanso-session` with `path` = the base.

- Board templates live in `shared/boardTemplates.ts` (used by `POST /api/boards` and the new-board dialog).
- `canEdit`/`isOwner` in the UI are cosmetic only; the server role from `GET /api/boards/:id` drives them. Both are false while offline (`useOffline()`), so the board is read-only then.
- PWA (`@vite-pwa/nuxt`, `pwa` in `nuxt.config.ts`; production builds only, `devOptions` off): manifest `/manifest.webmanifest` (linked by `<NuxtPwaManifest />` in `app.vue`), icons in `public/` (generated PNGs of the `AppLogo` glyph), workbox `generateSW` `/sw.js`. Precaches the static build; NetworkFirst (3 s timeout) runtime caches `kanso-pages` (page loads except `/auth/*`, `/api/*`, login/register/reset pages) and `kanso-api` (`GET /api/me`, `/api/boards`, `/api/boards/:id`, `/api/cards/:id` only; never SSE, attachments, auth or non-GET), plus shared `kanso-icons` (`/api/_nuxt_icon`). Those two hold one user's data: `app/plugins/cacheOwner.client.ts` runs `syncCacheOwner` (`app/utils/pwaCache.ts`, owner id in localStorage `kanso:cache-owner`) after mount and on every session change, deleting them on sign-out (and while signed out) and when the user differs. New per-user caches: add to `userCacheNames`. To offline-enable another read, add its path to the `kanso-api` pattern. `registerType: 'prompt'`: `app.vue` shows an "Update available · Reload" toast on `$pwa.needRefresh`; the user menu shows "Install app" when `$pwa.showInstallPrompt`. Offline state: `useOffline()` (`useState`, false during SSR/hydration, kept by `app/plugins/network.client.ts`); `OfflineBanner` in the layout; `useBoard` reopens the EventSource and refreshes when back online.
- `app/middleware/auth.global.ts` guards pages; the login page (`app/pages/login/index.vue`; `/login/2fa` is the second step) shows only OAuth providers with credentials set (`/api/auth/providers`). OAuth callbacks live in `server/routes/auth/<provider>.get.ts` (callback URL `http://localhost:3000/auth/<provider>`); `upsertOAuthUser` links to an existing account by email only when the provider reports it verified.
